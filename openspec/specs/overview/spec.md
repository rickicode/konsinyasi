## Purpose

A multi-platform field sales management system that enables sales teams to conduct outlet visits
with consignment cycle management, product placement tracking, photo documentation, and HPP cost
calculations. The system supports offline-first mobile operations with background synchronization,
complemented by a web dashboard for administrative oversight and reporting.

## Requirements

### Requirement: SystemCapabilities

The system SHALL provide the following capabilities:

- Offline-first mobile architecture with visit drafts stored locally and synchronized via BackgroundSyncService when connectivity returns
- Shared image compression policy implemented separately per platform (Canvas API for web, Flutter ImageCompressor for mobile) to reduce upload bandwidth and storage costs
- Idempotency keys as v4 UUIDs for visit submissions to prevent duplicate processing during network retries
- Traffic-light color coding system (VisitCycleColor, ConsignmentAge) for visual prioritization of aging consignment inventory
- HPP (Harga Pokok Produksi) calculation service with recipe-based raw material composition and cascading recalculation on cost changes
- Geofence validation with configurable radius and distance calculation for location-verified visit submissions
- Separate API service layer per client platform (DashboardApiService, AuthApiService for web; DioClient with structured error mapping for mobile) with TanStack Query integration on web
- Soft-delete pattern for outlets, products, and users to maintain referential integrity with historical visit records
- One-time refresh token rotation for mobile authentication security
- Public storefront API (PublicStorefrontService) unauthenticated for customer-facing outlet discovery, separate from authenticated management APIs

## Technical Notes

- **Architecture Style**: Layered architecture with clean separation between presentation, domain, and infrastructure layers. The backend uses Cloudflare Workers with service-oriented decomposition, while frontend clients (Svelte web, Flutter mobile) implement MVVM/MVP patterns with reactive state management. This separation enables independent platform evolution, offline resilience, and testable business logic.
- **Security Model**: Dual authentication scheme: cookie-based sessions for web clients and OAuth2-style access/refresh token pairs for mobile clients. Role-based access control (RBAC) with two primary roles (staff and owner) enforced at route level via requireAuth/requireOwner guards and service-level permission checks. SessionService validates tokens on each request; financial data redaction applied based on role in VisitResultTransformationService. Rate limiting enforced per IP and username via RateLimitService.
- **External Integrations**: Cloudflare D1 (SQLite edge database), Cloudflare R2 (object storage for photos), Cloudflare Workers (serverless compute platform), Geolocation APIs (browser Geolocation API, Flutter Geolocator), Image processing (Canvas API, Flutter image libraries), Local notifications (mobile platform APIs), Background task scheduling (WorkManager on Android, equivalent iOS), Native maps applications (geo: URI scheme)
