# Notification Specification

> Generated by openlore v1.0.0 on 2026-07-26 01:44

## Purpose

Manages local notifications for visit reminders and synchronization status, including
initialization, permission handling, immediate display, scheduled reminders, and cancellation.

## Requirements

> `mobile/lib/core/notifications/notification_service.dart`

### Requirement: InitializeNotificationService

The system SHALL initializes the notification plugin, timezone data, and creates the notification channel for the application.

#### Scenario: FirstTimeInitialization

- **GIVEN** Notification service has not been initialized
- **WHEN** initialize is called
- **THEN** Plugin is initialized, timezone data is loaded, and service is marked as initialized
- **AND** Notification channel is created on Android

#### Scenario: AlreadyInitialized

- **GIVEN** Notification service is already initialized
- **WHEN** initialize is called
- **THEN** Returns true without re-initializing

#### Scenario: AndroidPermissionRequest

### Requirement: ShowImmediateNotification

The system SHALL displays an immediate notification to the user with the given title, body, and optional payload.

#### Scenario: ShowBasicNotification

- **GIVEN** Notification service is initialized
- **WHEN** showNotification is called with valid parameters
- **THEN** Notification is displayed with provided title and body

#### Scenario: ShowNotificationWithPayload

- **GIVEN** Notification service is initialized
- **WHEN** showNotification is called with payload
- **THEN** Notification is displayed with payload for tap handling
- **AND** Payload is attached for navigation handling

### Requirement: ScheduleDailyReminder

The system SHALL schedules a daily recurring reminder notification at the specified hour.

#### Scenario: ScheduleVisitReminder

- **GIVEN** Notification service is initialized and permission granted
- **WHEN** scheduleDailyReminder is called
- **THEN** Daily reminder is scheduled for next occurrence of specified time
- **AND** Notification repeats daily at the same time

#### Scenario: ScheduleForNextDay

- **GIVEN** Current time is after the scheduled hour
- **WHEN** scheduleDailyReminder is called
- **THEN** Reminder is scheduled for tomorrow at specified time
- **AND** Time is adjusted to next day if specified time has passed

### Requirement: DismissToast

> Implementation: `toast` in `src/web/lib/stores/toast.svelte.ts` · confidence: heuristic

The system SHALL removes a toast notification from the active list by its identifier.

#### Scenario: DismissExistingToast

- **GIVEN** A toast with id 'abc-123' exists in the active toasts
- **WHEN** dismiss is called with 'abc-123'
- **THEN** The toast with id 'abc-123' is removed from the active toasts list

#### Scenario: DismissNonExistentToast

- **GIVEN** No toast with id 'xyz-789' exists in the active toasts
- **WHEN** dismiss is called with 'xyz-789'
- **THEN** The active toasts list remains unchanged

#### Scenario: DismissOneOfManyToasts

- **GIVEN** Multiple toasts exist including one with id 'target-id'
- **WHEN** dismiss is called with 'target-id'
- **THEN** Only the toast with 'target-id' is removed; other toasts remain

### Requirement: Initialize

The system SHALL initialize the notification service and update state with initialization status, then request permission if initialization succeeds.

#### Scenario: SuccessfulInitializationWithPermission

<!-- openlore-test: priority=high tags=smoke (auto) -->

- **GIVEN** NotificationService is not yet initialized
- **WHEN** initialize is called and service.initialize returns true
- **THEN** state reflects initialized=true and permission status
- **AND** state.initialized SHALL be set to true
- **AND** state.permissionGranted SHALL be set to the result of requestPermission

#### Scenario: FailedInitialization

<!-- openlore-test: tags=regression (auto) -->

- **GIVEN** NotificationService fails to initialize
- **WHEN** initialize is called and service.initialize throws an exception
- **THEN** state reflects initialized=false and contains error message
- **AND** state.initialized SHALL be set to false

#### Scenario: InitializationSucceedsButPermissionDenied

<!-- openlore-test: priority=high (auto) -->

- **GIVEN** NotificationService initializes but permission is denied
- **WHEN** initialize is called, service.initialize returns true, and requestPermission returns false
- **THEN** state reflects initialized=true and permissionGranted=false
- **AND** state.permissionGranted SHALL remain false

### Requirement: ScheduleDailyReminder

The system SHALL schedule a daily reminder notification at the specified hour if the notification service is initialized.

#### Scenario: ScheduleReminderWhenInitialized

- **GIVEN** Notification service is initialized
- **WHEN** scheduleDailyReminder is called with hour=8
- **THEN** daily reminder is scheduled via NotificationService
- **AND** NotificationService.scheduleDailyReminder SHALL be called with the specified hour

#### Scenario: NoOpWhenNotInitialized

- **GIVEN** Notification service is not initialized
- **WHEN** scheduleDailyReminder is called but state.initialized is false
- **THEN** no scheduling occurs and method returns immediately
- **AND** NotificationService.scheduleDailyReminder SHALL NOT be called
