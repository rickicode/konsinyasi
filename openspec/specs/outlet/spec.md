refreshing outlet data.

## Requirements

### Requirement: OutletValidation

The system SHALL validate Outlet according to these rules:

- Name must be non-empty string (min 1 character)
- Address must be non-empty string (min 1 character)
- Latitude must be a number between -90 and 90 inclusive
- Longitude must be a number between -180 and 180 inclusive
- Status must be either 'active' or 'inactive'
- On creation, status defaults to 'active' if not provided
- On update, all fields are optional but must pass validation if provided
- Soft delete: deleted_at is null for active records, set to timestamp for deleted records

#### Scenario: CreateNewOutlet

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** A user provides valid outlet details with name, address, latitude, and longitude
- **WHEN** outletCreateSchema is validated and submitted
- **THEN** Outlet is created with generated id, timestamps, and active status
- **AND** Status defaults to 'active' if not specified

#### Scenario: UpdateOutletDetails

- **GIVEN** An existing outlet with stored properties
- **WHEN** outletUpdateSchema is validated with partial fields and submitted
- **THEN** Outlet record is updated with new values and updated_at timestamp is refreshed
- **AND** Only provided fields are updated
- **AND** Unchanged fields retain their existing values

#### Scenario: SoftDeleteOutlet

- **GIVEN** An existing active outlet
- **WHEN** delete operation is performed
- **THEN** Outlet's deleted_at is set to current timestamp and outlet becomes hidden from active queries
- **AND** Outlet remains recoverable due to soft delete

#### Scenario: CaptureOutletLocation

- **GIVEN** An outlet exists and a user captures location data
- **WHEN** location data is submitted with GPS coordinates
- **THEN** Outlet's latitude, longitude, location_accuracy_m, and location_captured_at are updated
- **AND** Location accuracy and capture time are recorded

#### Scenario: RecordOutletVisit

- **GIVEN** An outlet exists and a visit is recorded
- **WHEN** visit is logged against this outlet
- **THEN** Outlet's last_visit_at reflects the most recent visit time
- **AND** last_visit_at is updated to current timestamp

### Requirement: PaginationQueryValidation

The system SHALL validate PaginationQuery according to these rules:

- page must be a positive integer
- limit must be a positive integer
- limit must not exceed 100

#### Scenario: DefaultPaginationValues

- **GIVEN** A paginated list endpoint is requested
- **WHEN** No explicit page or limit is provided
- **THEN** The response uses page 1 and limit 20
- **AND** page defaults to 1
- **AND** limit defaults to 20

#### Scenario: ValidatePaginationParameters

<!-- openlore-test: tags=smoke,regression (auto) -->

- **GIVEN** A paginated list endpoint is requested
- **WHEN** Invalid page or limit values are provided
- **THEN** Validation errors are returned for invalid values
- **AND** page must be a positive integer
- **AND** limit must be a positive integer not exceeding 100

### Requirement: PaginationMetaValidation

The system SHALL validate PaginationMeta according to these rules:

- page must be an integer
- limit must be an integer
- total must be an integer
- total_pages must be an integer

#### Scenario: CalculateTotalPages

- **GIVEN** A paginated query has been executed
- **WHEN** PaginationMeta is constructed
- **THEN** total_pages is calculated as ceil(total / limit)

### Requirement: PaginatedListValidation

The system SHALL validate PaginatedList according to these rules:

- data must be an array
- meta must contain valid PaginationMeta

#### Scenario: ReturnPaginatedData

- **GIVEN** A paginated endpoint returns results
- **WHEN** Data is fetched with pagination parameters
- **THEN** A PaginatedList with data array and meta information is returned

### Requirement: ApiErrorValidation

The system SHALL validate ApiError according to these rules:

- code must be a non-empty string
- message must be a non-empty string
- status when present must be a valid HTTP status code number

#### Scenario: ValidationFailureResponse

<!-- openlore-test: tags=smoke,regression (auto) -->

- **GIVEN** A request fails validation in the Hono request pipeline
- **WHEN** onError handler catches ZodValidationError
- **THEN** ApiError is returned with code, message, and 400 status
- **AND** error.code equals 'VALIDATION_ERROR'
