# Sync Specification

> Generated by openlore v1.0.0 on 2026-07-26 01:44
> Source files: mobile/lib/data/local/app_database.dart

## Purpose

Mengelola sinkronisasi data antara perangkat mobile dan server: pull cache untuk data warung dan
produk, serta push antrian kunjungan offline.

## Entities

### SyncRecord

> `mobile/lib/data/local/app_database.dart`

Tracks last synchronization timestamp per entity type for incremental sync optimization.

**Properties:**

| Name       | Type     | Description                             |
| ---------- | -------- | --------------------------------------- |
| key        | string   | Entity type or sync category identifier |
| lastSyncAt | datetime | Timestamp of last successful sync       |

## Requirements

### Requirement: SyncRecordValidation

The system SHALL validate SyncRecord according to these rules:

- key must be unique per entity type
- lastSyncAt must not be in the future

#### Scenario: TrackIncrementalSyncCheckpoint

- **GIVEN** App has previously synced data
- **WHEN** Sync operation completes successfully
- **THEN** SyncRecord updated with current timestamp for entity key
- **AND** Subsequent syncs use lastSyncAt as watermark

#### Scenario: InitializeSyncTracking

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** No prior sync exists for entity
- **WHEN** First sync operation completes
- **THEN** SyncRecord created with key and current timestamp after first sync
- **AND** Initial sync fetches all data without watermark

### Requirement: CheckOnlineStatus

The system SHALL mengevaluasi konektivitas perangkat untuk menentukan apakah sinkronisasi dapat dilakukan.

#### Scenario: DeviceIsOnline

- **GIVEN** Perangkat terhubung ke jaringan (WiFi, mobile, atau ethernet)
- **WHEN** isOnline dipanggil
- **THEN** Mengembalikan true

#### Scenario: DeviceIsOffline

- **GIVEN** Perangkat tidak terhubung ke jaringan apapun
- **WHEN** isOnline dipanggil
- **THEN** Mengembalikan false

### Requirement: SynchronizeAllData

The system SHALL melakukan sinkronisasi penuh: pull data warung dan produk dari server, serta push kunjungan tertunda dari lokal ke server.

#### Scenario: OfflineDevice

- **GIVEN** Perangkat dalam keadaan offline
- **WHEN** syncAll dipanggil
- **THEN** Mengembalikan SyncStatus.offline tanpa melakukan operasi jaringan

#### Scenario: SuccessfulFullSync

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** Perangkat online dengan data lokal yang perlu disinkronkan
- **WHEN** syncAll dipanggil
- **THEN** Mengembalikan SyncStatus.success
- **AND** Data warung dan produk diperbarui di cache lokal
- **AND** Kunjungan tertunda dikirim ke server dan dihapus dari draft lokal
- **AND** Notifikasi sukses ditampilkan untuk kunjungan yang tersinkron

#### Scenario: SyncFailure

<!-- openlore-test: tags=regression (auto) -->

- **WHEN** syncAll dipanggil
- **THEN** Mengembalikan SyncStatus.error
- **AND** Notifikasi kegagalan ditampilkan dengan detail error

### Requirement: SynchronizeAllData

The system SHALL initiates full synchronization of local data with remote servers, updating the sync state throughout the process.

#### Scenario: SuccessfulFullSynchronization

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** Application is online and has pending local changes
- **WHEN** sync() is called
- **THEN** State updates to success with confirmation message
- **AND** SyncStatus transitions to syncing
- **AND** SyncManager.syncAll() is invoked

#### Scenario: OfflineSynchronizationAttempt

- **GIVEN** Device has no network connectivity
- **WHEN** sync() is called
- **THEN** State updates to offline with appropriate message
- **AND** SyncStatus transitions to syncing
- **AND** SyncManager.syncAll() returns offline status

#### Scenario: FailedSynchronizationWithError

<!-- openlore-test: tags=regression (auto) -->

- **GIVEN** Network error or server failure occurs during sync
- **WHEN** sync() is called
- **THEN** State updates to error with retry message
- **AND** SyncStatus transitions to syncing
- **AND** SyncManager.syncAll() returns error status

#### Scenario: PreventConcurrentSynchronization

- **GIVEN** Sync is already in progress
- **WHEN** sync() is called while status is syncing
- **THEN** No state change occurs
- **AND** SyncStatus remains idle
- **AND** No sync operation is performed

### Requirement: InitializeBackgroundSyncFramework

The system SHALL the service shall initialize the workmanager framework and register the callback dispatcher as a flutter entry point for background task execution.

#### Scenario: FirstTimeInitialization

- **GIVEN** Application is starting up
- **WHEN** initializeBackgroundSync is called
- **THEN** WorkManager is initialized with the callback dispatcher
- **AND** WorkManager is not previously initialized

#### Scenario: IdempotentInitialization

<!-- openlore-test: tags=regression (auto) -->

- **GIVEN** Application startup is invoked again
- **WHEN** initializeBackgroundSync is called
- **THEN** No error is thrown and WorkManager remains configured
- **AND** WorkManager was previously initialized

### Requirement: SchedulePeriodicBackgroundSync

The system SHALL the service shall register a periodic background task with the configured frequency and network constraints for automatic data synchronization.

#### Scenario: DefaultFrequencyScheduling

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** No frequency parameter is provided
- **WHEN** scheduleBackgroundSync is called
- **THEN** Periodic task is registered with 15-minute interval
- **AND** Default 15-minute frequency is applied

#### Scenario: MinimumFrequencyEnforcement

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** A frequency shorter than 15 minutes is provided
- **WHEN** scheduleBackgroundSync is called
- **THEN** Periodic task is registered with 15-minute interval
- **AND** Frequency is coerced to minimum 15 minutes

#### Scenario: UpdateExistingPeriodicWork

- **GIVEN** A periodic task was previously registered
- **WHEN** scheduleBackgroundSync is called
- **THEN** Existing task is replaced with new configuration
- **AND** Existing work policy is set to update

### Requirement: CancelBackgroundSync

#### Scenario: CancelActiveTask

- **GIVEN** A periodic sync task is active
- **WHEN** cancelBackgroundSync is called
- **THEN** Periodic task is removed and will no longer execute
- **AND** Task was previously scheduled

#### Scenario: CancelWithNoActiveTask

<!-- openlore-test: tags=regression (auto) -->

- **WHEN** cancelBackgroundSync is called
- **THEN** No error is thrown

### Requirement: DispatchBackgroundSyncTask

The system SHALL the service shall execute a complete data synchronization cycle when invoked by the workmanager task dispatcher, including authentication validation, data sync, and completion notification.

#### Scenario: SuccessfulSyncDispatch

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** Valid access token exists and sync succeeds
- **WHEN** WorkManager executes the sync task
- **THEN** All data is synchronized and completion notification is displayed
- **AND** Sync completes successfully
- **AND** Notification is shown

#### Scenario: SkipSyncWithoutAuthentication

<!-- openlore-test: priority=high (auto) -->

- **GIVEN** No valid access token is present
- **WHEN** WorkManager executes the sync task
- **THEN** Sync is aborted and no notification is shown
- **AND** Sync is skipped
- **AND** No notification is shown

#### Scenario: HandleSyncFailure

<!-- openlore-test: tags=regression (auto) -->

- **GIVEN** An exception occurs during sync execution
- **WHEN** WorkManager executes the sync task
- **THEN** Error is logged and task returns true to prevent retry
- **AND** Error is logged
- **AND** Task is marked complete

#### Scenario: IgnoreNonSyncTasks

- **GIVEN** An unrecognized task name is received
- **WHEN** WorkManager executes an unknown task
- **THEN** Task is skipped and marked complete
- **AND** Task returns true immediately
