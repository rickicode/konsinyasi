# Auth Specification

> Generated by openlore v1.0.0 on 2026-07-26 01:44

## Purpose

Manages authentication state and user session lifecycle including login, logout, session
restoration, and error handling.

## Entities

### LoginResponse

> `mobile/lib/data/models/auth_model.dart`

Represents the response payload returned by the backend upon successful authentication, containing
user identity information and session tokens.

**Properties:**

| Name         | Type   | Description                                       |
| ------------ | ------ | ------------------------------------------------- |
| id           | string | Unique identifier for the authenticated user      |
| email        | string | Email address of the authenticated user           |
| username     | string | Username of the authenticated user                |
| name         | string | Display name of the authenticated user            |
| role         | string | Role assigned to the user in the system           |
| accessToken  | string | Short-lived access token for API authorization    |
| refreshToken | string | Long-lived token used to obtain new access tokens |
| tokenType    | string | Type of token issued (e.g., Bearer)               |

### LoginRequest

> `mobile/lib/data/models/auth_model.dart`

Represents the request payload sent to the backend to initiate an authentication session.

**Properties:**

| Name     | Type   | Description                                      |
| -------- | ------ | ------------------------------------------------ |
| username | string | Username credential for authentication           |
| password | string | Password credential for authentication           |
| device   | string | Device identifier indicating the client platform |

### AuthToken

> `mobile/lib/core/storage/secure_storage.dart`

A pair of OAuth2 tokens (access and refresh) persisted securely on the device for authenticated API
communication.

**Properties:**

| Name         | Type   | Description                                                                     |

### Requirement: LoginResponseValidation

The system SHALL validate LoginResponse according to these rules:

- id must be present and non-null in JSON
- email must be present and non-null in JSON
- username must be present and non-null in JSON
- name must be present and non-null in JSON
- role must be present and non-null in JSON
- access_token may be absent or null in JSON
- refresh_token may be absent or null in JSON
- token_type may be absent or null in JSON

### Requirement: AuthTokenValidation

The system SHALL validate AuthToken according to these rules:

- Access token must be stored with key 'access_token' in secure storage
- Refresh token must be stored with key 'refresh_token' in secure storage
- On Android: encrypted shared preferences must be enabled
- On iOS: storage must use account name 'konsi_secure_storage'
- Clear tokens operation must delete both access and refresh token keys atomically (sequential await)
- Access token setter does not accept null; refresh token setter accepts null for explicit invalidation

#### Scenario: PersistTokensAfterLogin

- **WHEN** setAccessToken() and setRefreshToken() are called
- **THEN** Both access and refresh tokens are written to secure device storage
- **AND** Token is stored in platform secure storage (encrypted shared preferences on Android, keychain on
  iOS)

#### Scenario: UpdateAccessTokenOnRefresh

<!-- openlore-test: priority=high (auto) -->
