## Requirements

### Requirement: APIAuthentication

The API SHALL require authentication via: None (rate-limited by IP and username), None (rate-limited by IP), Session cookie or refresh token in body, Session cookie (web) or access token (mobile), None, Session Cookie, Bearer JWT, requireAuth, requireAuth, requireOwner, Session-based, None (device capability), None (External Service), Not specified

#### Scenario: AuthenticatedRequest

- **GIVEN** a request with valid authentication credentials
- **WHEN** the request is processed
- **THEN** the request is authenticated successfully

#### Scenario: UnauthenticatedRequest

- **GIVEN** a request without authentication
- **WHEN** accessing a protected endpoint
- **THEN** the response status is 401 Unauthorized

### Requirement: POSTUser/Session

The API SHALL support `POST /login` to authenticate a user with username and password, creating either a web session (cookie-based) or mobile tokens (access/refresh token pair).

#### Scenario: WebLoginSuccess

<!-- openlore-test: priority=high tags=smoke (auto) -->

- **GIVEN** User provides valid username and password
- **WHEN** POST /login with device=web or default
- **THEN** 200 OK with user object; session cookie is set
- **AND** Rate limit: max 5 attempts per 15-minute window

#### Scenario: MobileLoginSuccess

<!-- openlore-test: priority=high tags=smoke (auto) -->

- **GIVEN** User provides valid username and password
- **WHEN** POST /login with device=mobile
- **THEN** 200 OK with access_token, refresh_token, expires_in, and user details
- **AND** Rate limit: max 5 attempts per 15-minute window

#### Scenario: LoginFailure

<!-- openlore-test: priority=high tags=regression (auto) -->

- **GIVEN** User provides invalid credentials or user is inactive
- **WHEN** POST /login with invalid credentials
- **THEN** 401 Unauthorized with AuthError message
- **AND** Rate limit: max 5 attempts per 15-minute window

### Requirement: POSTSession

The API SHALL support `POST /refresh` to exchange a valid refresh token for a new access/refresh token pair using one-time rotation (the old refresh token is invalidated).

#### Scenario: TokenRefreshSuccess

<!-- openlore-test: priority=high tags=smoke (auto) -->

- **GIVEN** Valid, non-expired refresh token belonging to active user
- **WHEN** POST /refresh with valid refresh_token
- **THEN** 200 OK with new access_token, refresh_token, expires_in, and user details
- **AND** Rate limit: max 10 attempts per 15-minute window

#### Scenario: TokenRefreshFailure

<!-- openlore-test: priority=high tags=regression (auto) -->

- **WHEN** POST /refresh with invalid/expired refresh_token
- **THEN** 401 Unauthorized with AuthError message
- **AND** Rate limit: max 10 attempts per 15-minute window
