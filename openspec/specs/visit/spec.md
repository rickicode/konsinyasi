# Visit Specification

> Generated by openlore v1.0.0 on 2026-07-26 01:44
> Source files: src/shared/schemas/visit.schema.ts, src/worker/db/schema.ts, mobile/lib/data/local/app_database.dart, mobile/lib/data/models/visit_model.dart, src/web/features/visits/stores/visit-draft.svelte.ts

## Purpose

Orchestrates visit lifecycle processing including geofence validation, consignment cycle management
(pickups from closed cycles, drops to open cycles), age-based color coding for UI, and geographic
distance calculations for location verification.

## Entities

## Requirements

### Requirement: VisitValidation

The system SHALL validate Visit according to these rules:

- Idempotency key is required and must be non-empty
- Client coordinates must be valid finite numbers
- GPS accuracy must be non-negative if provided
- At least one of pickups or drops should be present (implied by business logic)
- Geofence override reason should be provided when override is true

#### Scenario: SubmitVisit

- **GIVEN** Salesperson at outlet location with valid outlet assignment
- **WHEN** visit submission is sent with valid idempotency key
- **THEN** Visit is recorded with pickups, drops, and location data
- **AND** Distance to outlet is within geofence radius or override is approved

#### Scenario: IdempotentVisitSubmission

<!-- openlore-test: tags=regression (auto) -->

- **GIVEN** Previous visit submission with same idempotency key
- **WHEN** same idempotency key is used again
- **THEN** Duplicate submission is rejected or returns existing result
- **AND** Idempotency key must be unique

#### Scenario: GeofenceOverride

- **GIVEN** Salesperson outside geofence radius
- **WHEN** geofence_override is true
- **THEN** Visit can still be submitted with override flag
- **AND** Override reason should be provided

### Requirement: PickupLineValidation

The system SHALL validate PickupLine according to these rules:

- Cycle ID is required and must be non-empty
- Quantity sold must be non-negative integer
- Quantity returned good must be non-negative integer
- Quantity returned damaged must be non-negative integer
- Total returned cannot exceed originally dropped quantity (implied)

#### Scenario: CloseCycleWithSalesAndReturns

- **GIVEN** Cycle at outlet with remaining stock
- **WHEN** pickup line is submitted in visit
- **THEN** Cycle is marked as closed with recorded quantities
- **AND** All quantities must be non-negative integers

### Requirement: DropLineValidation

The system SHALL validate DropLine according to these rules:

- Product ID is required and must be non-empty
- Quantity dropped must be positive integer
- Notes are optional

#### Scenario: DropNewCyclesAtOutlet

- **GIVEN** Salesperson with available inventory
- **WHEN** drop line is submitted in visit
- **THEN** New cycles are recorded as dropped at outlet
- **AND** Quantity must be positive integer

### Requirement: VisitCycleStateValidation

The system SHALL validate VisitCycleState according to these rules:

- Age hours must reflect actual time since dropped_at
- Color must be one of: red, yellow, green
- Quantity dropped must be non-negative integer

#### Scenario: CheckCycleFreshness

- **GIVEN** Cycle dropped at outlet some time ago
- **WHEN** visit state is loaded for outlet
- **THEN** Cycle displays with appropriate color indicator
- **AND** Color changes based on age thresholds

### Requirement: VisitPhotoValidation

The system SHALL validate VisitPhoto according to these rules:

- Visit ID is required
- Photo key is required
- URL is required
- Sequence must be a number
- Note and uploaded_by can be null

#### Scenario: UploadVisitPhoto

- **AND** Photo is stored with generated key

- distanceM must be non-negative
- geofenceRadiusM must be positive
- createdAt must be a valid date
- outletName defaults to 'Warung'
- userName defaults to 'User'

- geofenceOverride defaults to false
