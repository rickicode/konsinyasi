# Visit-draft Specification

> Generated by openlore v1.0.0 on 2026-07-26 01:44

## Purpose

Manages the state of offline visit drafts queue, providing capabilities to list enriched draft
summaries with outlet information and pickup/drop counts, refresh the list, and delete individual
drafts.

## Requirements

> `mobile/lib/providers/visit_draft_provider.dart`

### Requirement: InitializeAndLoadVisitDrafts

> Implementation: `loadVisitDraft` in `src/web/lib/visit.ts` · confidence: heuristic

The system SHALL initializes the notifier state by loading all visit drafts from local storage, enriching each draft with outlet details and pickup/drop counts, and sorting results by creation date descending.

#### Scenario: SuccessfulInitializationWithMultipleDrafts

<!-- openlore-test: tags=smoke (auto) -->

- **GIVEN** Multiple visit drafts exist in local storage with associated outlet IDs and pickup/drop JSON data
- **WHEN** build is called during notifier initialization
- **THEN** State emits sorted list of VisitDraftItem with enriched outlet and count information
- **AND** Each VisitDraftItem contains outlet name from OutletLocalDataSource or 'Warung tidak diketahui' if
  outlet not found
- **AND** Pickup count derived from pickupsJson
- **AND** Drop count derived from dropsJson
- **AND** Results sorted with newest first

#### Scenario: EmptyDraftList

- **GIVEN** No visit drafts exist in local storage
- **WHEN** build is called during notifier initialization
- **THEN** State emits empty list
- **AND** Outlet name defaults to 'Warung tidak diketahui'
- **AND** Pickup and drop counts are zero

#### Scenario: DraftWithMalformedJSONData

- **GIVEN** Visit draft exists with malformed pickupsJson or dropsJson
- **WHEN** build processes draft with invalid JSON
- **THEN** State emits list with zero counts for malformed fields without crashing
- **AND** Invalid JSON returns empty list via _decodeList fallback
- **AND** Outlet lookup still attempted if outletId is present

### Requirement: RefreshVisitDraftList

The system SHALL reloads all visit drafts from local storage, re-enriches with outlet data and counts, and updates the notifier state with fresh data.

#### Scenario: RefreshAfterNewDraftsAdded

- **GIVEN** New visit drafts have been added since last load
- **WHEN** refresh is called
- **THEN** State emits updated list including new drafts
- **AND** State transitions through loading to data

#### Scenario: RefreshAfterExternalModifications

- **GIVEN** Existing drafts have been modified or deleted externally
- **WHEN** refresh is called
- **THEN** State emits list reflecting current local storage state
- **AND** State transitions through loading to data

### Requirement: DeleteVisitDraft

The system SHALL permanently removes a visit draft from local storage by its idempotency key and refreshes the list state.

#### Scenario: DeleteExistingDraft

- **GIVEN** Visit draft with matching idempotency key exists in local storage
- **WHEN** deleteDraft is called with valid idempotencyKey
- **THEN** Draft is removed from local storage and state emits updated list without the draft
- **AND** State refreshes to exclude deleted draft

#### Scenario: DeleteNonExistentDraft

- **GIVEN** No visit draft with matching idempotency key exists
- **WHEN** deleteDraft is called with non-existent idempotencyKey
- **THEN** Local storage delete is attempted, state refreshes with unchanged list
- **AND** State refreshes showing unchanged list

## Technical Notes

- **Dependencies**: VisitDraftLocalDataSource, OutletLocalDataSource
